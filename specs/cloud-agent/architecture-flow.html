Cloud Agent 目标架构（决议⑧：云服务端 = 标准 ZCode host 本体 + cloud 叠加）

浏览器用两条语义不同的通道接同一个云服务端进程；账号域与执行域各有唯一所有者。对应 specs/cloud-agent/00-overview.md §3 与 07-connection-architecture.md §3。

链路语义（与 spec 对应的硬边界）

# 链路 所有者 / 边界
1 浏览器 → host /ws 账号域（登录、套餐、设置、模型目录）。web 模式同款服务通道，零新增装配；token 正文不进浏览器
2 浏览器 → /ws/cloud/tasks/:taskId 沙箱 attachment：按 capability 白名单代理执行域；无 secret read、无 provisioning target、无本机 fallback
3 host → cloud 叠加层 run envelope：账号登录态（含套餐 zhipu-account）或静态 config，二选一互斥；白名单凭据
4 cloud 叠加层 → 沙箱生命周期 provider 是唯一生命周期 owner；创建用持久 operation 幂等键，结果未知走对账，不盲建第二个
5 沙箱 → cloud 叠加层（出站 WSS） bridge 认证绑定 run/generation/epoch；投影 ingest 后才 ACK；断网只释放网络 facade，不等于 Agent 结束
6 沙箱 → GitHub（受控 push） git grant 单次兑换、60s、绑定 task/run/repo/purpose；只推 taskBranch
7 cloud 叠加层 → GitHub（App API） App 私钥不出云服务端；PR/checks 由叠加层 effect worker 执行

关键点：云服务端确实运行 host 本体（所以"禁本机"不是"不装配"），但云任务与浏览器执行请求的落点只有沙箱 attachment，部署机 host 执行域不构成任何隐式 fallback（03 §2）。
